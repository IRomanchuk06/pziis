## 2. Программа «Expert» (tools/expert.py)

### 2.1. Критерий

Файл рассматривается как последовательность байтов. Пусть `N` — число
байтов, `n_i` — число вхождений байтового значения `i` (i = 0…255).
При равномерном распределении ожидаемое число вхождений каждого значения
`e = N / 256`. Статистика критерия:

```
chi2 = Σ (i=0..255) (n_i − e)² / e
```

При гипотезе H0 («байты равновероятны и независимы») статистика имеет
распределение хи-квадрат с k = 256 степенями свободы (в оригинальной
Expert.exe — тот же критерий).

**p-значение**: `p = Q(k/2, chi2/2) = Γ(128, chi2/2) / Γ(128)` — регулярная
верхняя неполная гамма-функция. Реализована на чистом `math` без scipy:
ряд для `P(a,x)` при `x < a+1` и цепная дробь (модифицированный алгоритм
Лента) иначе — алгоритм Numerical Recipes (`tools/expert.py`,
функция `igamc`). Гипотеза о случайности отвергается при малых p
(и при аномально малых chi2 — p, близких к 1).

### 2.2. Вердикты

Формулировки — как в методичке (программа Expert.exe выдаёт три значения):

* «Последовательность не является случайной»
* «Последовательность подозрительна»
* «Последовательность почти подозрительна»
* (четвёртый возможный исход — тест пройден: «Последовательность случайна»)

В методичке числовые пороги не заданы, поэтому в реализации использованы
стандартные двусторонние уровни значимости (chi2 критически велик **или**
критически мал — «слишком хорошее» совпадение с равномерным законом тоже
свидетельствует о неслучайности):

| Условие | Вердикт |
|---|---|
| p ≤ 0.01 или p ≥ 0.99 | Последовательность не является случайной |
| p ≤ 0.05 или p ≥ 0.95 | Последовательность подозрительна |
| p ≤ 0.10 или p ≥ 0.90 | Последовательность почти подозрительна |
| иначе | Последовательность случайна (тест пройден) |

По методичке, результаты «подозрительна»/«почти подозрительна» означают,
что файл содержит **похожую на случайную** последовательность и требуют
применения более мощных тестов; вывод «не является случайной» — файл
заведомо содержит неслучайную структуру.

## 4. Датчик rand() как в MS Visual Studio

### 4.1. Формула и реализация

Встроенный датчик Microsoft CRT — линейный конгруэнтный генератор по модулю
2^32 (реализован явно, `cpp/gen_msvc.cpp`):

```
State = State * 214013 + 2531011;      // арифметика по модулю 2^32
return (State >> 16) & 0x7fff;         // 15-битный результат rand()
```

Начальное состояние — `srand(0)`, как в примере методички. В файл записываются
младшие байты последовательных значений `rand()` (аналог `memcpy(hMem + i,
&dwRand, 1)` из примера): 20 000 000 байт → `demo_output/data/msvc_rand.bin`.

### 4.2. Анализ

| Тест | Значение | p | Итог |
|---|---:|---:|---|
| Expert (chi2, 256 ст. св.) | chi2 = 29.66 | p ≈ 1 − 1e-16 | **не является случайной** (chi2 аномально мал) |
| Частотный тест | 49.9987 % единиц | 0.746436 | пройден |
| Тест пар байтов (65536 ячеек) | chi2 = 20 447.14 | ≈ 1 − 1e-16 | **провал** |
| Longest run (M=128) | chi2 = 3.19 | 0.363917 | пройден |

(вывод `demo_output/expert_results.txt`, `demo_output/extra_tests.txt`)

### 4.3. Вывод о качестве

Вердикт «не является случайной» получен из-за **аномально малого** chi2:
распределение байтов «слишком равномерное». Это ожидаемый дефект датчика:
младшие биты LCG по модулю 2^32 имеют короткие периоды (бит k состояния
повторяется с периодом 2^(k+1); используемые биты 16…23 состояния образуют
последовательность с периодом 2^24 ≈ 16.7 млн — меньше длины файла), и в
пределах периода каждый байт встречается почти одинаковое число раз, т. е.
выборка ведёт себя «равномернее» истинно случайной. Независимость при этом
отсутствует: тест пар байтов даёт chi2 = 20 447 при 65 535 степенях свободы.
Датчик `rand()` MS VS предсказуем и непригоден ни для моделирования высокого
качества, ни тем более для криптографии. **Полученный «провал» — нормальный,
ожидаемый результат задания**: он демонстрирует непригодность встроенного
арифметического генератора.

## 5. Криптографический генератор CryptGenRandom (CryptoAPI)

### 5.1. Листинг (cpp/gen_crypt.cpp)

Использованы функции из примера методички:
`CryptAcquireContext(..., PROV_RSA_FULL, CRYPT_VERIFYCONTEXT)`,
`CryptGenRandom`, `CryptReleaseContext`.

```cpp
#include <windows.h>
#include <wincrypt.h>
#include <cstdio>
#include <cstdlib>

int main(int argc, char** argv) {
    const char*         path  = (argc > 1) ? argv[1] : "crypt_out.bin";
    const unsigned long total = (argc > 2) ? strtoul(argv[2], 0, 10) : 1048576UL;

    HCRYPTPROV hProv = 0;

    if (!CryptAcquireContext(&hProv, NULL, NULL, PROV_RSA_FULL, CRYPT_VERIFYCONTEXT)) {
        std::fprintf(stderr, "CryptAcquireContext failed, GetLastError()=%lu\n",
                     static_cast<unsigned long>(GetLastError()));
        return 1;
    }

    FILE* out = std::fopen(path, "wb");
    if (out == NULL) {
        std::fprintf(stderr, "error: cannot open %s for writing\n", path);
        CryptReleaseContext(hProv, 0);
        return 2;
    }

    static BYTE lpGoop[65536];
    unsigned long written = 0;
    int failed = 0;

    while (written < total) {
        DWORD cbGoop = static_cast<DWORD>(total - written);
        if (cbGoop > sizeof(lpGoop)) cbGoop = sizeof(lpGoop);

        if (!CryptGenRandom(hProv, cbGoop, lpGoop)) {
            std::fprintf(stderr, "ошибка генерации данных, GetLastError()=%lu\n",
                         static_cast<unsigned long>(GetLastError()));
            failed = 1;
            break;
        }
        if (std::fwrite(lpGoop, 1, cbGoop, out) != cbGoop) {
            std::fprintf(stderr, "error: write failed\n");
            failed = 1;
            break;
        }
        written += cbGoop;
    }

    std::fclose(out);
    if (hProv) CryptReleaseContext(hProv, 0);
    if (failed) return 3;
    std::printf("OK: CryptGenRandom wrote %lu bytes to %s\n", written, path);
    return 0;
}
```

Программа получает контекст криптопровайдера RSA Full с флагом
`CRYPT_VERIFYCONTEXT` (без доступа к ключевым парам — достаточно для
генерации случайных данных), порциями по 64 КиБ заполняет буфер
`CryptGenRandom` и записывает его в выходной файл. Для MS VS 6.0, согласно
сноске методички, может потребоваться `#define _WIN32_WINNT 0x0500`;
в заголовках MinGW нужные объявления доступны без него.

### 5.2. Статус сборки и запуска

## 6. Собственный генератор из таблицы 1 методички

### 6.1. Формула

Формулы в таблице 1 PDF читаемы; выбран **генератор (1)**:

```
x_{t+1} = (1176·x_t + 1476·x_{t-1} + 1776·x_{t-2}) mod (2^32 − 5)
```

Модуль m = 2^32 − 5 = 4 294 967 291 (простое число), рекуррентность третьего
порядка, период T_max ≈ 2^96. Реализация — `cpp/gen_own.cpp`: 64-битная
арифметика без переполнения (коэффициенты < 2^11, слагаемые < 2^43), seed'ы
0x1A2B3C4D, 0x9E3779B9, 0x12345678; в файл записываются 32-битные значения
в формате little-endian (формат случайных целых для батареи DIEHARD):
3 000 000 слов × 4 байта = **12 МБ > 11 МБ** → `demo_output/data/own_gen.bin`.

Ключевой фрагмент:

```cpp
static const uint64_t M = (1ULL << 32) - 5ULL; // 2^32 - 5 = 4294967291

uint64_t OwnGen::next() {
    // x_{t+1} = (1176*x_t + 1476*x_{t-1} + 1776*x_{t-2}) mod (2^32 - 5)
    const uint64_t xn = (1176ULL * x2 + 1476ULL * x1 + 1776ULL * x0) % M;
    x0 = x1;  x1 = x2;  x2 = xn;
    return xn;
}
```

### 6.2. Анализ (Expert + 3 простых теста)

| Тест | Значение | p | Итог |
|---|---:|---:|---|
| Expert (chi2, 256 ст. св.) | chi2 = 242.34 | 0.720715 | **случайна (тест пройден)** |
| Частотный (монобитный) | 49.9972 % единиц | 0.586167 | пройден |
| Тест пар байтов (65536 ячеек) | chi2 = 65 288.63 | 0.751597 | пройден |
| Longest run (M=128, NIST) | chi2 = 1.47 | 0.689606 | пройден |

### 6.3. Вывод о качестве

Собственный генератор (1) из таблицы 1 успешно проходит критерий хи-квадрат
и все три простых теста: байты равномерны, соседние байты независимы,
распределение максимальных серий единиц соответствует теоретическому.
В отличие от `rand()` MS VS, рекуррентность третьего порядка по простому
модулю не проявляет короткопериодных дефектов младших байтов на длине
12 МБ. Генератор пригоден для моделирования (Монте-Карло, имитация), но,
как и любой детерминированный ГПСЧ с известной рекуррентностью, не
предназначен для криптографии: восстановив три подряд идущих выходных
слова, можно вычислить всю последовательность (решение линейной системы
по модулю 2^32−5).

## 8. Вывод

**Семантическая составляющая** (что означают полученные результаты).
Критерий хи-квадрат с 256 степенями свободы измеряет отклонение эмпирических
частот байтов от равномерного закона: величина chi2 имеет среднее 256 и
стандартное отклонение ≈ 22.6, поэтому значимы как слишком большие значения
(структурированность, неравномерность), так и аномально малые («сверхравномерность»
— признак коротких периодов детерминированного датчика). Результаты работы
семантически разделились на три класса. Файлы программного кода и архив —
заведомо неслучайные объекты с высокой избыточностью, и критерий это надёжно
зафиксировал (chi2 от 2.6·10^3 до 5.7·10^6, p < 1e-300). Арифметический
датчик rand() MS VS при формально ровной частотной картине оказался
неслучайным — его «слишком хорошее» равномерие (chi2 = 29.66) и провал теста
пар байтов раскрывают короткопериодную структуру младших битов LCG, то есть
последовательность предсказуема. Собственный генератор (1) из таблицы 1 и
криптографический CryptGenRandom/urandom показали статистически согласованные
с гипотезой случайности результаты — хи-квадрат и три дополнительных теста
(частотный, пар байтов, longest run) не выявили ни неравномерности, ни
зависимостей соседних байтов, ни аномальных серий. Таким образом, «случайность»
по отношению к ГПСЧ — это не абсолют, а совокупность проверяемых свойств
(равномерность, независимость, отсутствие коротких циклов), и разные датчики
обладают ими в разной мере: простые арифметические генераторы годятся лишь
для неответственных задач, хорошо спроектированные рекуррентные генераторы
по простому модулю — для моделирования, а криптографические генераторы с
энтропийным источником — для защиты информации.

**Прагматическая составляющая** (практические рекомендации).
1. Проверка произвольных файлов программой «Expert» — быстрый экспресс-фильтр:
   если файл претендует на «случайные данные» (шифртекст, сжатый архив без
   заголовков), а chi2 аномален — данные структурированы или повреждены;
   сам по себе положительный результат не гарантирует криптостойкости и
   требует более мощных батарей (DIEHARD, NIST SP 800-22, > 11 МБ входных
   данных). 2. Встроенные датчики типа `rand()` MS VS непригодны ни для
   качественного моделирования, ни для криптографии: при необходимости
   следует использовать либо тщательно подобранные рекуррентные генераторы
   по простому модулю (как формула (1) таблицы 1, период ≈ 2^96), либо
   современные библиотечные ГПСЧ (Mersenne Twister, PCG, xoshiro), а для
   защиты информации — исключительно криптографические источники
   (CryptGenRandom/BCryptGenRandom в Windows, /dev/urandom/getrandom в
   Linux): их преимущество — не «более красивый» chi2, а непредсказуемость,
   опирающаяся на накопленную энтропию системы. 3. Инженерно полезен и сам
   инструментарий: весь цикл (сборка C++, кросс-компиляция MinGW, запуск
   Windows-.exe под wine, анализ Python) воспроизводимо выполняется одной
   командой `./run.sh` в docker-окружении без установки чего-либо на хост.

## Приложение. Состав проекта и воспроизведение

```text
lab_4/
├── run.sh                  # единственная команда: сборка + запуск + сохранение вывода
├── Dockerfile              # цели: base → lab4 (g++, python3, MinGW) → winetest (+ wine)
├── docker-compose.yml      # проект lab_4, сервисы lab4 и winetest
├── cpp/
│   ├── gen_msvc.cpp        # датчик rand() как в MS VS (State*214013+2531011)
│   ├── gen_own.cpp         # генератор (1) из таблицы 1: mod (2^32-5)
│   └── gen_crypt.cpp       # CryptGenRandom (CryptoAPI) -> gen_crypt.exe (MinGW)
├── tools/
│   ├── expert.py           # «Expert»: chi2, 256 ст. св., p = Q(128, chi2/2), вердикты
│   ├── extra_tests.py      # частотный, пар байтов, longest run (NIST M=128)
│   ├── make_zip.py         # создание тестового архива .zip
│   └── make_table.py       # сравнительная таблица -> demo_output/summary_table.md
├── scripts/                # demo.sh, run_analysis.sh, wine_run.sh (выполняются в контейнере)
├── demo_output/            # только реально захваченный вывод программ
│   ├── build.log, generate.log, expert_results.txt, extra_tests.txt,
│   ├── summary_table.md, cryptgen_wine.txt, run.log
│   └── data/ (msvc_rand.bin, own_gen.bin, crypt_out.bin, urandom.bin, archive.zip)
└── report/report.md        # этот отчёт
```

Запуск: `./run.sh` (сборка образов, генерация файлов, все анализы, попытка
wine — итоговые числа могут отличаться для urandom.bin/crypt_out.bin, т. к.
это истинно случайные данные).

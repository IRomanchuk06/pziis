# Лабораторная работа 6. Применение OpenSSL

Знакомство с CLI OpenSSL, тест скорости (`openssl speed`), симметричное
и асимметричное шифрование файлов, хэширование и самоподписанный
сертификат X.509. Среда — Docker-контейнер `ubuntu:24.04` с
OpenSSL 3.x (ставится из apt при сборке образа).

## Как запустить

```bash
cd lab_6
./run.sh
```

Одна команда: собирает образ `lab6:latest` (docker compose, проект
`lab_6`), запускает сценарий в контейнере и сохраняет вывод.

Требования: `docker` + `docker compose` v2 (на хосте больше ничего
не нужно и ничего не устанавливается). Прогон занимает ~30 секунд
(`openssl speed` — 1 с на алгоритм).

## Что делает сценарий

1. Выводит версию OpenSSL, список команд и алгоритмов.
2. `openssl speed -seconds 1 -elapsed` для aes-256-cbc, aes-128-cbc,
   chacha20 (недоступен в speed 3.0.x — честно пропускается), sha256,
   rsa2048 и ed25519.
3. Создаёт `file.txt` (97 Б) и `file.bin` (4 МиБ из `/dev/urandom`):
   - симметрично шифрует/расшифровывает их aes-256-cbc,
     camellia-256-cbc, des3 и rc4 (rc4 — через legacy provider);
     проверяет `cmp`, показывает заголовок `Salted__`, замеряет время
     на 4 МиБ с фиксированным ключом;
   - RSA-2048: `pkeyutl` OAEP-SHA256 шифрование/расшифрование малого
     файла + демонстрация ожидаемой ошибки на файле 300 Б;
   - Ed25519: подпись и проверка подписи (`pkeyutl -rawin`);
   - хэши md5/sha1/sha256 + перекрёстная проверка с `sha256sum`.
4. Создаёт самоподписанный сертификат X.509 (RSA-2048, 365 дней, с
   SAN/KeyUsage/EKU/BasicConstraints) и разбирает его состав
   (`openssl x509 -text`), затем проверяет цепочку `openssl verify`.

Примечания:

- Каждый повторный прогон создаёт новый случайный `file.bin`, новую
  пару ключей и новый сертификат — хэши, серийные номера и точные
  времена будут отличаться от примеров в отчёте; скорости
  (`openssl speed`) сопоставимы.
- Контейнер запускается от uid текущего пользователя, поэтому файлы в
  `demo_output/` не принадлежат root.

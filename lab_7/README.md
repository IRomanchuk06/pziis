# Лабораторная работа 7. Методика оценки безопасности кода

Строится поверх ЛР3: «свой алгоритм» — safe-хранилище из ЛР3 (`app/own/`),
«предоставленный алгоритм» — вторая реализация того же функционала с типовыми
дефектами (`app/provided/`). Для них создана формальная методика оценки
(5 критериев) и скрипт `app/evaluate.py`, который выполняет её целиком внутри
контейнера: статический AST-анализ, негативные прогоны, дампы памяти
(gdb gcore) с поиском секретов, анализ журналов и нагрузочный тест — и
выдаёт итоговую таблицу баллов и вердикты.

## Запуск

```bash
./run.sh
```

Требования на хосте: только Docker + Docker Compose (контейнеру нужны
`--cap-add=SYS_PTRACE` и `seccomp=unconfined` — для дампов памяти).

## Что получается в demo_output

| Файл | Содержимое |
|---|---|
| `evaluation_report.md` | итоговый отчёт методики: критерии, измеренные значения, баллы, вердикты |
| `evaluation_results.json` | все измеренные значения в машиночитаемом виде |
| `dumps/{own,provided}_p{1,2,3}_*.core` | дампы памяти (3 точки × 2 реализации) + `*.strings.txt`, `*.matches.txt`, `*.gdb.log`, `evidence_*.txt` |
| `dumps/session_*_dump.transcript.txt` | реальные транскрипты сценария дампов |
| `negative_*.transcript.txt` | транскрипты негативных прогонов (падения provided видны по Traceback) |
| `logs/provided.log` | журнал provided — конфиденциальные значения пишутся в лог в открытом виде |
| `load_own.json`, `load_provided.json` | результаты нагрузочного теста (2000 записей) |
| `dumps/tokens.txt` | маркеры секретов прогона (для воспроизведения поиска) |

## Ключевой результат прогона

| Критерий (вес) | own | provided |
|---|---:|---:|
| C1 Обработка невалидных данных (0.15) | 5 | 0 |
| C2 Lifetime секретов в ОЗУ (0.30) | 5 | 0 |
| C3 Качество ключевого материала (0.20) | 5 | 0 |
| C4 Поведение под нагрузкой (0.10) | 5 | 5 |
| C5 Конфиденциальные данные в ОЗУ/журналах (0.25) | 5 | 0 |
| **Итог (0–5)** | **5.00 — принят** | **0.50 — отклонён** |

В дампах provided все 5 секретных маркеров находятся в т.ч. после удаления;
в дампах own — ни одного. Все детали: `demo_output/evaluation_report.md`,
полный отчёт: `report/report.md`.

## Структура

```
lab_7/
├── app/
│   ├── own/            # «свой алгоритм» — safe-хранилище из ЛР3 (vault.py, main.py)
│   ├── provided/       # «предоставленный алгоритм»: secrets в str, XOR-ключ из
│   │                   #   random (weak PRNG), MD5 для паролей, логирование секретов,
│   │                   #   без затирания и валидации (store.py, main.py)
│   ├── bench_impl.py   # нагрузочный тест одной реализации (JSON)

├── demo_output/        # артефакты прогона (создаётся run.sh)
├── report/report.md    # отчёт
├── Dockerfile, docker-compose.yml, run.sh, requirements.txt
```

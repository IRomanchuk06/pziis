# Оценка безопасности кода по методике (ЛР7)

Сравнение: `own` -- свой алгоритм (safe-подход ЛР3) и `provided` -- предоставленный
алгоритм. Все значения таблиц -- реальные результаты проверок, выполненных в
контейнере (статический AST-анализ, негативные прогоны, дампы gdb gcore, нагрузочный
тест). Маркеры прогона: `dumps/tokens.txt`.

## 1. Методика (критерии, проверка, метрика, шкала)

| ID | Критерий | Вес | Способ проверки | Метрика | Шкала 0–5 |
|---|---|---|---|---|---|
| C1 | Обработка невалидных данных и аварийных ситуаций | 0.15 | динамическая: батарея из 10 невалидных входов (неизвестная команда, неверный тип/формат, лишние аргументы, операции над несуществующими записями, дубликат, verify для не-пароля); фиксируются отклонение ([err]), молчаливое принятие и аварийное завершение | robustness = доля входов, корректно отклонённых без падения | 5: 100%; 4: ≥90%; 3: ≥70%; 2: ≥50%; 1: ≥30%; 0: <30% |
| C2 | Lifetime секретов в памяти | 0.30 | динамическая: дампы памяти (gdb gcore) в 3 точках (ввод / обновление / удаление); strings -a + поиск 5 секретных маркеров | доля секретных маркеров, НАЙДЕННЫХ в дампе после удаления (главный индикатор остаточных данных); находки в точках ввода/обновления фиксируются | 5: в p3 не найдено ни одного секрета; 0: найдены все; иначе 5·(1−доля) |
| C3 | Качество ключевого материала | 0.20 | статическая (AST): источник случайности (os.urandom/secrets vs random), KDF для паролей (PBKDF2/scrypt vs MD5), стандартный аутентифицированный шифр (cryptography AES-GCM vs самодельный); динамическая: длина ключа и энтропия байт выходного потока генератора (информационно) | CSPRNG-источник (0/2) + KDF паролей (0/2) + аутентифицированный шифр (0/1) | 0..5 (сумма компонентов) |
| C4 | Поведение под нагрузкой / на больших объёмах | 0.10 | динамическая: 2000 конфиденциальных записей, фазы add/update/delete в отдельном процессе; замер wall/CPU/RSS | успешность фаз; avg мс/операцию; прирост RSS КБ/запись; замедление удаления относительно добавления | 5: все фазы успешны, avg ≤5 мс/оп, ≤10 КБ/запись, delete ≤10×add; −1 за каждое нарушение; 0 при сбое фазы |
| C5 | Работа с конфиденциальными данными в ОЗУ и журналах | 0.25 | статическая (AST): наличие механизма затирания (erase/scrub/wipe/zero), вызовы логирования с секретными аргументами; динамическая: поиск 5 секретных маркеров в журнале приложения и транскрипте сессии | утечки в журналах: 3·(1−доля утёкших маркеров); затирание: 2 (есть) / 0 (нет) | 0..5 (сумма компонентов) |

Итог: `Σ балл(критерия)·вес` (0–5). Вердикты: ≥4.0 — **принят**;
2.5–3.9 — **требует доработки**; <2.5 — **отклонён**.

## 5. C3 -- ключевой материал

| Параметр | own | provided |
|---|---|---|
| Длина ключа, бит | 256 | 256 |
| Источник | PBKDF2-HMAC-SHA256 (600000 итераций) из мастер-пароля, соль os.urandom(16) | random.getrandbits(8) -- Mersenne Twister, weak PRNG |
| Энтропия выходного потока, бит/байт (1024 Б) | 7.8077 | 7.8285 |
| Пример ключа (hex) | 95cb0286fa3de35e0ba9119b118c79fb51fc807768223cb58be98cd3dd52e4fb | a2c2488573c0f427e1859584723d6ff0a5efbb3436d66f59fe2441535846aa61 |

Примечание: частотная энтропия у обоих источников близка к 8 бит/байт --
распределение байт НЕ выявляет слабый PRNG; слабый источник выявляется
только аудитом источника (AST): `random.getrandbits` (Mersenne Twister,
предсказуемый) против PBKDF2/os.urandom.

# Лабораторная работа 1. Оценка защищённости разработанного приложения

Консольное приложение на Python 3.12: пользователи с ролями, аутентификация
по логину/паролю (PBKDF2-HMAC-SHA256), сессии с тайм-аутом, конфиденциальные
данные с шифрованием AES-256-GCM, журнал аудита, разграничение доступа
(admin / user / guest).

## Запуск

```bash
./run.sh
```

Одна команда: собирает образ (`python:3.12-slim` + `cryptography`), запускает
демонстрационный сценарий в контейнере от непривилегированного пользователя и
сохраняет вывод в `demo_output/demo_run_<дата>.log` (копия —
`demo_output/demo_run.log`).

Интерактивный режим (после сборки):

```bash
docker compose run --rm -T app python cli.py
```

## Структура

```
lab_1/
├── app/
│   ├── security.py   # PBKDF2-HMAC-SHA256 (200k итераций), AES-256-GCM
│   ├── sessions.py   # сессии с TTL, инвалидация при logout/удалении пользователя
│   ├── audit.py      # журнал аудита (JSON-строки, файл 0600)
│   ├── storage.py    # JSON-хранилище: каталог 0700, файлы 0600, атомарная запись
│   ├── service.py    # бизнес-логика: роли, права, CRUD, поиск, аудит
│   ├── demo.py       # демонстрационный сценарий (CMD образа)
│   └── cli.py        # интерактивная консоль
├── Dockerfile
├── docker-compose.yml   # compose-проект lab_1
├── run.sh
├── demo_output/         # реально захваченный вывод запусков
└── report/report.md
```

## Модель доступа

| Операция                          | guest | user            | admin |
|-----------------------------------|-------|-----------------|-------|
| чтение/поиск неконфиденциальных   | да    | да              | да    |
| чтение/поиск конфиденциальных     | нет   | только своих    | да    |
| создание/изменение/удаление записей | нет | своих           | любых |
| управление пользователями         | нет   | нет             | да    |

## Пароли и ключи

Для демонстрации `MASTER_PASSWORD` и `ADMIN_PASSWORD` заданы в
`docker-compose.yml`. В реальной эксплуатации их следует передавать через
docker secrets / менеджер секретов и регулярно менять. Данные приложения
живут внутри контейнера (`/srv/data`) и не монтируются на хост.

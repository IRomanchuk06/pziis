# Лабораторная работа 2. Оценка защищённости сторонней программной системы

Оцениваемая система — приложение из `lab_1` (консольный менеджер
пользователей и данных: PBKDF2-пароли, сессии с тайм-аутом, AES-256-GCM,
роли, аудит). Разработана формальная методика оценки защищённости по четырём
политикам (ОС; компоненты и их взаимодействие; сеть; конфиденциальность
данных) и скрипт-аудитор `app/audit.py`, который выполняет 24 проверки
автоматически: 9 статических (анализ исходников и Dockerfile цели) и
15 динамических (тестовый прогон целевого приложения в изолированном
каталоге с известными аудиторским секретами и маркерами).

## Запуск

```bash
./run.sh
```

Одна команда: собирает образ аудитора (`python:3.12-slim` + `cryptography`),
запускает аудит в контейнере от непривилегированного пользователя и
сохраняет вывод в `demo_output/audit_run_<дата>.log` (копия —
`demo_output/audit_run.log`). Код lab_1 передаётся volume-маунтом только на
чтение:

```yaml
volumes:
  - ../lab_1/app:/srv/target:ro
  - ../lab_1/Dockerfile:/srv/inspect/Dockerfile:ro
```

Код возврата: `0` — все проверки пройдены, `1` — есть FAIL/SKIP.

## Что проверяется

- **ОС**: запуск без root; права на файлы данных (каталог 0700, файлы 0600);
  Dockerfile цели (зафиксированный базовый образ, USER non-root).
- **Компоненты и взаимодействие**: PBKDF2-HMAC-SHA256 и число итераций KDF;
  криптослучайные уникальные соли; отсутствие паролей-литералов в ядре;
  отклонение неверного пароля; хранилище пользователей без открытых паролей;
  тайм-аут сессии (статически и динамически); инвалидация токена при logout;
  полнота журнала аудита (allow/deny) и отсутствие в нём секретов;
  управляемая валидация ввода.
- **Сеть**: отсутствие сетевых API в коде; отсутствие слушателей приложения
  в `/proc/net/tcp*` (слушатель 127.0.0.11 — DNS-инфраструктура Docker,
  атрибутируется отдельно).
- **Конфиденциальность данных**: AES-GCM со случайным nonce; шифротекст
  конфиденциальных записей на диске; читаемость неконфиденциальных;
  отсутствие ключа и мастер-пароля в файлах данных; матрица прав
  guest/user/admin динамическим тестом.

Методика (критерии, ожидания, способы проверки) и разбор результатов —
в `report/report.md`.

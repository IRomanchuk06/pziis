# Лабораторная работа 5. Управление ключами

**Вариант выполнения:** Python 3.12 (стандартная библиотека), запуск в Docker-контейнере `python:3.12-slim`.
**Исходные данные алгоритма Диффи-Хеллмана:** `p = 134041249`, `α = 7`.

---

## 1. Постановка задачи

1. Реализовать алгоритм дискретного возведения в степень по модулю для
   32-разрядных чисел (собственная реализация быстрого возведения);
   сравнить результат и время выполнения с встроенной функцией
   `pow(b, e, m)`.
2. Реализовать алгоритм Диффи-Хеллмана для двух пользователей с
   параметрами `p = 134041249`, `α = 7`: сгенерировать два случайных
   32-разрядных числа `X1`, `X2` (`X < p`), вычислить открытые ключи
   `Y1 = α^X1 mod p`, `Y2 = α^X2 mod p` и показать, что общие секреты
   `(Y1)^X2 mod p` и `(Y2)^X1 mod p` равны.
3. Написать программу дискретного логарифмирования 32-разрядных чисел
   методом «baby-step giant-step» и определить `X` по известному
   `Y = α^X (mod p)`; проверить корректность восстановления.
4. Замерить и сравнить время выполнения возведения в степень по модулю
   и дискретного логарифмирования (`time.perf_counter`, несколько
   прогонов, среднее значение).
5. Оформить отчёт с описанием алгоритмов, результатами и выводом.

## 2. Краткое описание алгоритмов

### 2.1. Дискретное возведение в степень по модулю

«Наивное» вычисление `b^e mod m` (сначала возведение в степень, затем
взятие остатка) создаёт промежуточное число из `e·log2(b)` битов и
непригодно даже для 32-разрядных показателей. Стандартное решение —
**бинарный алгоритм (square-and-multiply) «справа налево»**:

```
result = 1; base = b mod m
пока e > 0:
    если младший бит e == 1: result = result * base mod m
    base = base^2 mod m
    e = e >> 1
```

Показатель рассматривается в двоичном представлении: на i-м шаге
`base = b^(2^i) mod m`, и в результат попадают только те степени, которым
соответствуют единичные биты показателя. Промежуточные значения никогда
не превышают `m^2`, поэтому все операции выполняются с 64-разрядными
числами. Сложность — `O(log2 e)` модульных умножений: для 32-разрядного
показателя это не более 32 умножений и 32 возведений в квадрат.

### 2.2. Алгоритм Диффи-Хеллмана

Схема согласования общего секретного ключа по открытому каналу.
Общие параметры: большое простое `p` и генератор `α` (первообразный
корень по модулю `p`).

1. Алиса выбирает секрет `X1`, Боб — секрет `X2` (случайные числа из
   `[2, p−2]`).
2. Открытые ключи: `Y1 = α^X1 mod p` (Алиса), `Y2 = α^X2 mod p` (Боб) —
   передаются по открытому каналу.
3. Каждый вычисляет общий ключ: Алиса — `K = (Y2)^X1 mod p`,
   Боб — `K = (Y1)^X2 mod p`.

Равенство ключей следует из коммутативности умножения показателей:
`K = α^(X1·X2) mod p`. Стойкость схемы основана на **сложности задачи
дискретного логарифмирования (DLP)**: злоумышленник видит `p`, `α`,
`Y1`, `Y2`, но для вычисления `X1` из `Y1` должен решить DLP, которое
при большом `p` вычислительно неразрешимо.

### 2.3. Метод baby-step giant-step (BSGS, Д. Шэнкс)

Пусть `y = α^x mod p`. Запишем `x = i·m + j`, где `m = ⌈√(p−1)⌉`,
`0 ≤ j < m`. Тогда `α^j = y·(α^(−m))^i`:

- **baby steps:** построить хэш-таблицу `{α^j → j}` для `j = 0..m−1`
  (последовательные умножения на `α`);
- **giant steps:** для `i = 0..m` вычислять `γᵢ = y·(α^(−m))^i` и искать
  `γᵢ` в таблице; первое совпадение даёт `x = i·m + j`.

Обращение `α^(−m)` вычисляется через малую теорему Ферма:
`α^(−m) ≡ (α^m)^(p−2) (mod p)`. Сложность — `O(√p)` операций и памяти
(компромисс «время–память» по Штаркеману): для `p = 134041249`
получаем `m = 11578` — таблица всего из ~11,6 тыс. элементов.
Найденный `x` дополнительно проверяется возведением в степень.

## 3. Проверка параметров

Программа перед выполнением обмена проверяет корректность параметров
(файл `app/modmath.py`):

| Проверка | Результат |
|---|---|
| `p = 134041249` простое (тест Миллера–Рабина) | да |
| Разложение `p − 1 = 134041248` | `2^5 · 3^2 · 11 · 29 · 1459` |
| Порядок `α = 7` по модулю `p` | `134041248 = p − 1` → 7 — первообразный корень (образующая группы) |

Так как `α` — образующая, дискретный логарифм существует для любого
`Y ≠ 0` и определён однозначно по модулю `p − 1`.

## 6. Вывод

**Семантическая составляющая.** В работе реализованы и согласованы между
собой три базовых примитива криптосистем с открытым ключом: быстрое
модульное возведение в степень, протокол Диффи-Хеллмана и дискретное
логарифмирование. Экспериментально подтверждена **асимметрия
вычислительной сложности**: прямая задача (возведение в степень)
выполняется за микросекунды — O(log p) умножений, тогда как обратная
(дискретный логарифм) даже оптимальным для небольших p методом BSGS
требует O(√p) операций, что на измеренных данных в ~400–1000 раз дороже.
Именно на этой асимметрии строится стойкость Диффи-Хеллмана: стороны
легко вычисляют общий ключ, а наблюдатель, видящий только `Y1`, `Y2`,
должен решить DLP. Одновременно показана и оборотная сторона: BSGS
восстановил оба секретных ключа по открытым значениям за ~1,3 мс —
32-разрядный модуль (`p ≈ 2^27`) не даёт никакой реальной стойкости,
поскольку √p ≈ 1,2·10^4 достижимо мгновенно. Отмечено также, что
корректность параметров критична: `p` должно быть простым, а `α` —
первообразным корнем (проверено: `p − 1 = 2^5·3^2·11·29·1459`, порядок
`α = 7` равен `p − 1`), иначе группа вырождается и пространство ключей
сужается.

**Прагматическая составляющая.** Из полученных результатов следуют
практические правила применения DH на практике. Во-первых, размер
модуля выбирается из требования, чтобы √p (точнее, сложность лучших
известных алгоритмов — для конечных полей это index calculus с
субэкспоненциальной сложностью) был недостижим: сегодня используются
`p` длиной 2048–4096 бит, либо группы эллиптических кривых (ECDH),
где аналогичная стойкость достигается при 256–384 битах. Во-вторых,
параметры (`p`, `α`) не стоит изобретать самостоятельно — берутся
стандартизованные группы (RFC 3526, тестовые группы TLS), так как
слабые или «подложенные» параметры делают протокол уязвимым, что
наглядно продемонстрировал наш эксперимент со взломом. В-третьих,
собственные реализации модульной арифметики уступают оптимизированным
библиотечным (наш `mod_pow` в 2,3 раза медленнее `pow` и на порядки —
OpenSSL), поэтому в production-коде криптографию выполняют
поверенными библиотеками, а самописный код используют только для
учебных целей. Наконец, методика замеров (`time.perf_counter`, заранее
подготовленные данные, многократные прогоны с усреднением) применима
для любых сравнительных бенчмарков и позволяет корректно оценивать
эксплуатационные характеристики криптопримитивов.

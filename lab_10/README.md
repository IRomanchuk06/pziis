# Лабораторная работа №10. Управление доступом к объектам операционной системы Linux

БГУИР. Разграничение доступа в Linux (классическая модель DAC: владелец /
группа / остальные), создание пользователей и групп, проверочная матрица
доступа к файлам и каталогам, управление процессами (kill), очистка.

Всё выполнение — внутри Docker-контейнера **Ubuntu 24.04** (в контейнере
скрипты работают от root — это штатно для администрирования). На хосте
ничего не устанавливается и не запускается, кроме docker/docker compose.
Без `--privileged` — используется обычный `docker run` (через compose).

## Запуск одной командой

```bash
./run.sh
```

Скрипт: собирает образ `lab_10:latest`, запускает контейнер (проект compose —
`lab_10`), сохраняет весь вывод в `demo_output/run_full.log` и удаляет
контейнер после завершения. Время работы — около 4–5 минут (включая ~2 минуты
этапа проверки остановки процессов).

## Схема эксперимента (по заданию)

- Группы `group_iit1`, `group_iit2`; пользователи `iit11`, `iit12`
  (group_iit1), `iit21` (group_iit2, **административные привилегии**: группа
  sudo + `NOPASSWD`), `iit22` (group_iit2), `iit3`.
- Каталог `pzs` и подпапки с правами R/W/X:
  - `pzs11` — только владелец (`700`, владелец `iit11`);
  - `pzs12` — только группа (`070`, владелец `root`, группа `group_iit1`);
  - `pzs13` — только остальные (`007`, владелец и группа `root`);
  - `pzs14` — все пользователи (`777`);
  - `pzs15` — только администратор/root (`700`, `root:root`).
- В `pzs11`–`pzs14` создаются файлы `file11`–`file55` со всеми комбинациями
  прав (чтение/запись/выполнение) для классов «владелец», «группа
  group_iit1», «остальные», «все», «администратор». Файлы `filex5`
  (file15/25/35/45/55) содержат `read testVariable`, остальные —
  `echo "Hello World"`; у всех файлов строка `#!/bin/bash`.
- Для каждого файла — реальные проверки `cat`, `echo >>`, `./файл` от имени
  iit11, iit12, iit21, iit22, iit3 и root → матрица OK/DENIED.
- Файлы `filex5` запускаются как процессы пользователя iit11; проверяется,
  кто может их остановить (`kill`), включая дополнительную попытку iit21
  через sudo.
- В каждой папке проверяются `ls`, `touch`, `rm` от каждого пользователя
  (папка восстанавливается из копии между субъектами).
- `cleanup.sh` удаляет файлы, папки, пользователей и группы; результат
  чистки виден в конце журнала.

## Особенности, обнаруженные при выполнении

1. Сценарий с правами «только выполнение» (например `100`) в Linux запустить
   нельзя: интерпретатор `#!/bin/bash` обязан открыть файл на чтение →
   `Permission denied` (код 126). Поэтому в матрице шага 14 запуск у
   `filex5` запрещён всем, кроме root (root читает файл с обходом DAC).
2. root не может исполнить файл, в котором не установлен ни один бит x
   (например `400`) — для выполнения нужен хотя бы один бит x.
3. Процессы `filex5` запускаются от iit11 так: root читает файл и передаёт
   его текст bash процесса iit11 через fifo (унаследованный дескриптор
   stdin). Это демонстрирует принцип «проверка прав выполняется при
   открытии файла»: чтение из уже открытого дескриптора прав не проверяет.
4. Остановить чужой процесс может только владелец (тот же UID) и root;
   iit21 — дополнительно через sudo (административные привилегии).
5. В каталоге с правами `777` (без sticky-бита) любой пользователь может
   удалить чужой файл: право на удаление определяется правами на каталог.
